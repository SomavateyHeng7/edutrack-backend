# Legacy Feature Parity Review

Reviewed: 2025-12-18

## 1. Course Catalog & Search — Missing
- Route definitions still expect full CRUD on the course catalog per [routes/api.php#L110-L144](routes/api.php#L110-L144), but `CourseController` only implements search, bulk create, and constraint helpers with no `index`, `store`, `show`, `update`, or `destroy` methods [app/Http/Controllers/API/Chairperson/CourseController.php#L19-L241](app/Http/Controllers/API/Chairperson/CourseController.php#L19-L241).
- Bulk creation does not capture permission, summer-only, senior-standing, or min-credit flags, so new courses lose required metadata [app/Http/Controllers/API/Chairperson/CourseController.php#L96-L121](app/Http/Controllers/API/Chairperson/CourseController.php#L96-L121) despite the schema supporting them [database/migrations/2025_11_11_052029_create_table_name_courses.php#L11-L22](database/migrations/2025_11_11_052029_create_table_name_courses.php#L11-L22).
- The controller lacks a `prerequisites` read endpoint even though the route expects it [routes/api.php#L134-L137](routes/api.php#L134-L137), preventing curriculum UI from loading prerequisite/corequisite lists as in the legacy stack.
- Only the bulk-create path writes audit records; updates and deletions would remain invisible to audit consumers [app/Http/Controllers/API/Chairperson/CourseController.php#L106-L112](app/Http/Controllers/API/Chairperson/CourseController.php#L106-L112).

## 2. Course Type Management (Flat Model) — Partial
- CRUD endpoints exist with duplicate checks [app/Http/Controllers/API/Chairperson/CourseTypeController.php#L23-L187](app/Http/Controllers/API/Chairperson/CourseTypeController.php#L23-L187), but bulk assignment writes a `curriculum_id` to the pivot even though the table has no such column [app/Http/Controllers/API/Chairperson/CourseTypeController.php#L192-L229](app/Http/Controllers/API/Chairperson/CourseTypeController.php#L192-L229) vs [database/migrations/2025_11_11_052330_create_table_name_department_course_types.php#L11-L27](database/migrations/2025_11_11_052330_create_table_name_department_course_types.php#L11-L27). This query will fail at runtime.
- The bulk assign endpoint does not verify faculty or curriculum access before rewriting assignments [app/Http/Controllers/API/Chairperson/CourseTypeController.php#L192-L229](app/Http/Controllers/API/Chairperson/CourseTypeController.php#L192-L229), so required safeguards from the legacy backend are missing.

## 3. Curriculum Lifecycle & Course Attachment — Partial
- `CurriculumController::upload` only accepts CSV/TXT, clears existing links, and repopulates required courses without regenerating constraints or elective rules [app/Http/Controllers/API/Chairperson/CurriculumController.php#L338-L506](app/Http/Controllers/API/Chairperson/CurriculumController.php#L338-L506), whereas the legacy Excel flow also seeded elective settings.
- Adding a curriculum course ignores year, semester, requirement, and override fields even though the model exposes them [app/Http/Controllers/API/Chairperson/CurriculumController.php#L133-L170](app/Http/Controllers/API/Chairperson/CurriculumController.php#L133-L170) vs [app/Models/CurriculumCourse.php#L14-L32](app/Models/CurriculumCourse.php#L14-L32).
- There is still no audit logging around curriculum course add/remove calls [app/Http/Controllers/API/Chairperson/CurriculumController.php#L133-L170](app/Http/Controllers/API/Chairperson/CurriculumController.php#L133-L170), so historical tracking from the legacy backend is lost.

## 4. Elective Rules & Free-Elective Settings — Partial
- The elective rule API is present [app/Http/Controllers/API/Chairperson/ElectiveRuleController.php#L21-L247](app/Http/Controllers/API/Chairperson/ElectiveRuleController.php#L21-L247), but `store` does not enforce uniqueness per curriculum/category, leaving the door open for duplicate rows that the legacy backend rejected.
- Category inference still depends on a single department course type per course [app/Http/Controllers/API/Chairperson/ElectiveRuleController.php#L48-L87](app/Http/Controllers/API/Chairperson/ElectiveRuleController.php#L48-L87); with the current course-type assignment gap, categories can not be trusted for credit pools.

## 5. Concentrations (Course Lists) — Missing
- Concentration creation writes camelCase keys directly [app/Http/Controllers/API/Chairperson/ConcentrationController.php#L30-L36](app/Http/Controllers/API/Chairperson/ConcentrationController.php#L30-L36), but the model expects snake_case fields and a `created_by_id` [app/Models/Concentration.php#L14-L27](app/Models/Concentration.php#L14-L27) per its migration [database/migrations/2025_11_11_052137_create_table_name_concentrations.php#L11-L23](database/migrations/2025_11_11_052137_create_table_name_concentrations.php#L11-L23); inserts therefore fail.
- Access control is left as a TODO (“add department/faculty logic as needed”) in both controllers [app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L21](app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L21) and [app/Http/Controllers/API/Chairperson/ConcentrationCourseController.php#L11-L35](app/Http/Controllers/API/Chairperson/ConcentrationCourseController.php#L11-L35), so chairpersons can cross faculties.
- Concentration course uploads only accept JSON arrays [app/Http/Controllers/API/Chairperson/ConcentrationCourseController.php#L133-L170](app/Http/Controllers/API/Chairperson/ConcentrationCourseController.php#L133-L170); there is no CSV/XLSX parser like the legacy implementation relied on.

## 6. Blacklists (Course Lists) — Partial
- CRUD endpoints enforce faculty scoping and audit logging [app/Http/Controllers/API/Chairperson/BlacklistController.php#L21-L279](app/Http/Controllers/API/Chairperson/BlacklistController.php#L21-L279), but creation/updating only accepts arrays of course IDs and does not process uploads [app/Http/Controllers/API/Chairperson/BlacklistController.php#L79-L145](app/Http/Controllers/API/Chairperson/BlacklistController.php#L79-L145), leaving the CSV pathway unported.

## 7. Curriculum Attachments (Concentrations & Blacklists) — Partial
- Blacklist attachment endpoints exist [app/Http/Controllers/API/Chairperson/CurriculumBlacklistController.php#L29-L223](app/Http/Controllers/API/Chairperson/CurriculumBlacklistController.php#L29-L223) but store only the link; there is no per-curriculum required-credit override on either the migration [database/migrations/2025_11_11_052524_create_table_name_curriculum_blacklists.php#L11-L29](database/migrations/2025_11_11_052524_create_table_name_curriculum_blacklists.php#L11-L29) or controller payloads.
- There are no equivalent endpoints to attach/detach concentrations or adjust their required-course counts; `CurriculumController::concentrations` merely lists assignments [app/Http/Controllers/API/Chairperson/CurriculumController.php#L172-L183](app/Http/Controllers/API/Chairperson/CurriculumController.php#L172-L183).

## 8. Supporting Capabilities — Partial
- Several chairperson endpoints skip faculty scoping entirely (e.g., concentration list/create) [app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L80](app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L80), so authorization parity is not preserved.
- Audit logging is inconsistent: course catalog updates, curriculum course edits, and concentration mutations do not emit logs, unlike the legacy system [app/Http/Controllers/API/Chairperson/CourseController.php#L19-L241](app/Http/Controllers/API/Chairperson/CourseController.php#L19-L241) and [app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L80](app/Http/Controllers/API/Chairperson/ConcentrationController.php#L18-L80).
- Student intake remains a stub returning mock data unless a manual `studentId` is provided [app/Http/Controllers/API/Student/CompletedCourseController.php#L11-L69](app/Http/Controllers/API/Student/CompletedCourseController.php#L11-L69), so authenticated student uploads and audits cannot function yet.
